# 一页技术说明

**模型与量化。** 使用 Apache-2.0 的 [all-MiniLM-L6-v2 ONNX 转换版](https://huggingface.co/Xenova/all-MiniLM-L6-v2/tree/751bff37182d3f1213fa05d7196b954e230abad9)，固定 revision `751bff37182d3f1213fa05d7196b954e230abad9`。模型目录同时提供 FP32 基线和同版本上游 INT8 量化 ONNX 权重。用 `npm run models` 获取，Transformers.js 使用 `dtype: 'q8'` 加载后者。按实际加载的 ONNX 与共享配置、分词器文件统计，FP32 为 91,100,283 B，INT8 为 23,685,047 B，压缩比约 3.85×。

**端侧运行。** 浏览器使用 Transformers.js 3.8.1 的特征提取管线，以均值池化和 L2 归一化生成 384 维向量。先检查 WebGPU 适配器，并用一次真实推理验证 WebGPU 会话；无适配器或初始化、试运行失败时自动改用 WASM。界面显示实际后端，并复用已初始化的模型。ONNX 和分词器由本地应用提供。

**数据和刷新。** Node 使用 seekdb-js 的 `seekdb` SDK。每个知识库对应一个带余弦 HNSW 和全文索引的集合，写入片段 ID、原文、来源文件名和向量。查询通过 `hybridSearch` 提供关键词及浏览器查询向量，由 seekdb 在数据库内执行融合排序。文本分片后以 8 条一批计算并写入，完成时等待 `refresh_index()`。片段 ID 由文件名、位置和文本计算，原样重试不会重复写入；更改文件内容按增量导入处理。一次操作固定集合，切换名称会清除界面旧结果。

**实验口径。** 固定样例由 12 段英文文本和 8 条人工标注查询组成，每条查询一条相关文档。仅比较同一模型的 FP32/INT8、批大小 1/8 以及可用的浏览器推理后端。每组做三轮写入和检索，分阶段记录耗时，报告中位数以及 Recall@5 和 nDCG@5。每组的模型加载时间包含一次试运行；首个业务查询和后续查询单列。



**本机结果。** Windows x64、Intel Core i5-13500H / Iris Xe、Edge 157.0.4341.46、Node 24.19.0、seekdb-js 1.4.0 嵌入式。模型首次下载权重时 FP32 151.8 s、INT8 46.8 s（含网络传输，受网络影响）。下表的初始化读取本机模型文件。详细计时与每条查询的名次见 [原始结果](benchmark-results.json)。

| 配置（批大小） | 初始化 / ms | 向量化 / 片段每秒 | 数据库写入 / 刷新 ms | 首查 / ms | 查询向量化 / 数据库检索 / 端到端 ms | Recall@5 / nDCG@5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FP32 WASM（1） | 2522.9 | 33.7 | 370.7 / 304.2 | 39.5 | 16.2 / 9.8 / 30.5 | 1.000 / 0.954 |
| INT8 WASM（1） | 239.5 | 47.9 | 341.3 / 403.6 | 42.2 | 12.6 / 7.8 / 24.7 | 1.000 / 0.954 |
| INT8 WASM（8） | 244.0 | 45.7 | 456.2 / 303.1 | 35.9 | 13.2 / 8.3 / 25.2 | 1.000 / 0.954 |
| INT8 WebGPU（8） | 1462.8 | 15.7 | 439.8 / 302.4 | 267.1 | 173.0 / 12.2 / 198.7 | 1.000 / 0.891 |

同批大小的 WASM 对比中，INT8 向量化吞吐提高约 42%，质量指标持平。批大小从 1 增至 8 将 12 个片段的写入请求从 12 次减到 2 次，但这组小样本里未提高吞吐。WebGPU 实际初始化并完成了检索，但本机耗时更长，nDCG@5 较同批大小的 WASM 低 0.063。此样本规模不足以推断更大知识库的性能。另用隐藏 WebGPU API 的浏览器会话验证了自动降级和界面提示。
