# 一页技术说明

读者在到期日当天仍能还书。借阅清单中一个比较符决定了当天是否被标为逾期。这个样例同时保留未归还过滤、输入顺序与空清单三项原有行为，便于把模型的改动与业务结果逐项核对。

| 步骤 | 数据从哪里来、到哪里去 |
| --- | --- |
| 资料导入 | context.py 扫描项目下一级模块目录中的 Markdown、Python 文件，把模块名、相对路径、正文、摘要写入 seekdb。同一运行目录重新导入时，以一个事务替换该命名空间内的行。 |
| 任务检索 | 将任务文本中的英文单词转为小写，执行带参数的 SQL，匹配模块名。返回行保留文件正文与相对路径，按路径排序。样例用 loans 命中 3 个文件，用 holds 作为无关资料。 |
| 状态保存 | PowerContext 的 SourceRepository 在其 SQLiteProfile 中按任务 id 写入 ContentSource。内容包含已完成事项、待办及实际测试结果。后续进程通过官方仓储读取日志中的最新项和序号，合并进开发上下文。 |
| 代码修改 | agent.py 把查询正文和恢复的基线结果交给 MiniMax CLI，将返回文本保存为候选文件。开发时检查候选差异，再采用该文件为修改后快照。 |
| 验证 | verify.py 对固定测试先后运行两个快照，检查返回值、用例失败原因、测试摘要、模型输出、状态写入与重启后的读回值，最后对规格做一次真实编辑并重新检索。 |

**适用范围。** 输入任务需要包含小写英文模块目录名或其大小写变体。资料按模块整文件选取，适合此小型工程；模块内代码符号与规格编号保留在正文里。借阅样例接收已规范化的 ISO 日期字符串。运行目录代表一份独立索引，顺序执行一次验证流程。正常复验仅需真实数据库和 Python 依赖；开发阶段的真实 MiniMax 请求已经随源码交付。

**来源。** 借阅样例、规格、测试和上下文模块为本题编写。MiniMax 生成的业务改动可在 evidence/minimax/ 对照。[PowerContext](https://github.com/oceanbase/powercontext) 通过已发布的 Python 包调用其官方持久化实现。[seekdb](https://github.com/oceanbase/seekdb) 通过 MySQL 协议查询。[MiniMax CLI](https://github.com/MiniMax-AI/cli) 通过 messages-file 接收上下文。
